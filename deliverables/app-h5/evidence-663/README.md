# evidence-663 · 取景器与拍照视野不一致（msg663 / msg664）

真机：vivo 1578472099005SJ（1080x2376，App 横屏 2376x1080），包名 com.jianti.app 2.0.0。
全部截图由 TRA 在测试机上自行复现，未让浩爷代拍。

## 一、问题复现（修复前）

同一机位、同一场景，先截实时取景器，再按快门截拍后定格：

| 文件 | 说明 |
|---|---|
| 00_before_viewfinder.png | 修复前·实时取景器 |
| 01_before_capture.png | 修复前·按快门后的定格画面 |

同一青色盒子像素测量（截图原始像素，2376x1080）：

| 对象 | 取景器 | 拍出来 | 比值 |
|---|---|---|---|
| 主青盒 宽 | 332 px | 508 px | **1.53×** |
| 主青盒 高 | 235 px | 284 px | 1.21× |
| 右侧第二个青盒 | 可见（x≈2216） | **完全消失** | — |

结论：拍照视野只有取景器的大约 **65%**（放大 1.53 倍），且取景框右侧的内容在照片里被裁掉。
这正是浩爷反馈的「取景器里框到的内容，拍出来被裁掉了」。

整幅结构对比（取景框区域 2292x800，灰度归一化后）：

| | 平均灰度差 | 差异 >30 的像素占比 | 相关系数 |
|---|---|---|---|
| 修复前 | 24.08 | 26.15% | 0.8088 |

## 二、根因（代码）

`deliverables/app-h5/index.html`：

- 取景器 `.finder-video` 用 CSS `object-fit:cover` 铺满 `.vf-view`（横屏矩形，宽高比约 2.865:1）。
  `cover` 会按容器宽高比把视频溢出的部分裁掉——取景器显示的是「视频按容器比例裁出来的那一块」。
- 旧拍照 `grabFinderFrame()` 却固定裁视频**正中间的 1:1 正方形**：
  `var side = Math.min(w, h); ctx.drawImage(v, sx, sy, side, side, ...)`
- 拍完 `.finder-still` 又用 `object-fit:cover` 把这个正方形贴回横屏矩形，
  于是再被上下裁一次。

即：**预览用的是「按容器比例裁切」，成像用的是「先正方形裁切、再按容器比例裁切」**，
两套几何不一致，所以取景和成片不是同一块画面。

## 三、改法

新增 `finderSourceRect(v)`，按 `object-fit:cover` 的同一套几何算出源矩形
（视频比容器宽就左右裁、比容器高就上下裁，居中），`grabFinderFrame()` 和
`freezeFinderFrame()` 都用它取同一块区域；输出画布也用同一宽高比，
`.finder-still` 的 `cover` 因此不再产生二次裁切。

顺带把输出分辨率上限压在 1600px 长边，控制上传体积，不放大原始像素。

## 四、修复后验证（真机，同一机位同一场景）

| 文件 | 说明 |

| 02_after_viewfinder.png | 修复后·实时取景器 |
| 03_after_capture.png | 修复后·按快门后的定格画面 |

同一红色物体像素测量：

| | 取景器 | 拍出来 | 偏差 |
|---|---|---|---|
| 宽 | 571 px | 573 px | +0.35% |
| 高 | 453 px | 453 px | 0% |
| 面积 | 205884 px² | 206863 px² | +0.48%（JPEG 压缩误差） |

整幅结构对比：

| | 平均灰度差 | 差异 >30 的像素占比 | 相关系数 |

结论：修复后取景器与照片为同一块画面（结构相关 0.9985），
边缘内容不再被裁，面积偏差在 JPEG 压缩误差范围内。

## 五、复现步骤（可复核）

1. `adb install -r jianti-2.0.0-debug.apk`
2. 启动后左滑进 home 屏 → 点中间相机按钮进取景器
3. 对同一场景先 `adb shell screencap` 截取景，再点快门后 `screencap` 截定格
4. 用同一物体做像素测量比较
