## 通用约定（全组适用）

| 约定 | 内容 |
|---|---|
| 基地址（官方） | `solve.mhq-ai.xyz:8000`。官方地址写死，板上不显示；网关 8000 是平台层顶部唯一入口，只做路由、鉴权、限流。协议（http/https）PRD 未写明，，本文档以下路径均写相对路径。 |
| 基地址（自有） | 用户在手机第 16 屏弹窗手填 IP，确认才生效；端口 PRD 未写明，本文档暂按 8000（未定：U21）。 |
| 认证（管理端 / 手机 App） | `Authorization: Bearer <登录 token>`。token 由登录接口发放；管理密码 6 位数字只在进管理时校验一次，管理内（审批、改卡等）不再重复传密码、不再重复校验。 |
| 认证（终端） | `X-Terminal-Id: <16 位设备 ID>` ＋ `Authorization: Bearer <终端 token>`。终端 token 如何发放（绑定时发还是预置），PRD 未写（未定：U22）。未绑定设备调业务接口一律拒收（见 A1 400）。 |
| 请求 / 返回格式 | 除 `POST /solve`（raw JPEG）外一律 `Content-Type: application/json`；返回一律 JSON。时间一律服务端时间，格式 `YYYY-MM-DD HH:mm:ss`，日期时间补零（与日志页格式一致）。 |
| 通用返回信封 | 成功：`{"code": 0, "message": "ok", "data": {...}}`；失败：`{"code": <非 0 码>, "message": "<给人看的一句话>", "data": null}`。`message` 只作展示，不作程序判断依据；程序只判 `code`。信封格式为本文档约定，骨架复核时如冲突以骨架为准（见附录 E）。 |
| 幂等 | 扣卡、预支、申请创建、审批均须服务端幂等：同一 `Idempotency-Key`（客户端每次操作生成一个 UUID，放在请求头）重复提交只执行一次，重复返回第一次的结果。终端 / App 离线重发、用户连点，都靠它防重扣、重复创建。 |
| 错误码总表 | 各接口下只列本接口特有的码；通用码见下表，终端 / App 收到后按“终端收到后怎么做”一列处理。 |

### 通用错误码

| 码值 | 含义 | 终端 / App 收到后怎么做 |
|---|---|---|
| 0 | 成功 | 正常走下一步 |
| 400 | 请求参数不对（缺必填、格式错、越界） | 不重试；按 `message` 就地提示，留在当前屏 |
| 401 | 未鉴权（缺 token、token 过期、终端未绑定） | 管理端跳登录页（第 9 屏）；终端跳设置页（第 7 屏）提示检查绑定，不自动重发 |
| 403 | 已鉴权但无权限（非管理员调管理接口、成员调转让/删除） | 不重试；提示“没有权限”，留在当前屏 |
| 404 | 资源不存在（job / 申请单 / 终端不存在） | 不重试；提示“记录不存在”，留在当前屏或回上一屏 |
| 409 | 状态冲突（已撤回的单再批、已批的单再批、重复扣卡） | 不重试；按服务端最新状态刷新本屏 |
| 429 | 限流 | 等 `Retry-After` 秒（无该头时等 5 秒）后由用户手动重试一次；仍 429 则提示“稍后再试”，不自动循环 |
| 500 | 服务端内部错 | 提示“服务开小差了，稍后再试”，留在当前屏，可手动重试 |
| 503 | 模型 / 上游未接通 | 提示“判题服务暂时接不通”，留在处理页或回思路页（见 A2）；不谎称已出结果 |

> 数字说明：以下字段凡写“演示值”的，均不是验收依据；凡写“未定”的，开发前须由 Nyx / 决策方定，定好再开发，不许黑盒。

## 第一组　网关对终端

### A1　POST /solve —— 拍题上传（F1）（未定：U1、U2、U22）

- **方法＋路径**：`POST /solve`
- **用途**：终端只拍照与发送，压到 8MB 以内发网关；网关鉴权、限流、查绑定后转判题解题服务。现有 server 上 `/solve` 收图已跑通，本接口是在现有基础上升级（字段补齐），不是从零新建。
- **请求头**：`X-Terminal-Id: <16 位纯数字，必填>`；`Authorization: Bearer <终端 token，必填>`；`Content-Type: image/jpeg`；`Content-Length: <字节数>`；`Idempotency-Key: <UUID，必填，同一张照片重发用同一个 key>`。
- **请求体**：raw JPEG 二进制（不是 multipart，不是 base64 JSON）。约束：必须是 JPEG；大小 ≤ 8MB（2026-11-08 由 2MB 改到 8MB，3.7MB 真图实测通过；板子压不到 2MB 也不拒收，只要在 8MB 以内）；一图多题时框内有几道是几道，服务端拆题。
- **手机拍题先判绑定码（已定，PRD v5.5 手机端开发需求，板子不做）**：手机拍完、发网关前先在本地判断画面里有无本方绑定二维码，能解析出 16 位设备 ID 即直接绑到当前家庭账号、不走解题，否则正常发网关解题；每拍一次判一次、本地轻量。板子不做此判断，板子只在设置里亮出自己的二维码。
- **返回（成功，HTTP 200，`code: 0`）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `data.job_id` | string，必填 | 本次判题任务 ID，终端拿它去轮询 A2；格式未定，本文档不编格式 |
| `data.stage` | string，必填 | 当前阶段，初值 `uploading`；五阶段取值：`uploading` 上传、`gateway` 网关、`model` 大模型、`nlp` NLP、`delivering` 下发 |
| `data.question_count` | integer | 本次识别到的题数；识别未完成时可为 `null`，终端不拿它当题数定稿 |
| `data.created_at` | string | 服务端接收时间，`YYYY-MM-DD HH:mm:ss` |

- **返回（失败）**：通用信封，`data: null`，码值见下表。失败时不建 job，不扣卡，不留“已拍题”记录（失败本身可记一条网关拒收日志，见 A11）。

| 码值 | HTTP | 含义 | 终端收到后怎么做 |
|---|---|---|---|
| 40001 | 400 | 设备号不对：`X-Terminal-Id` 不是 16 位纯数字，或未绑定任何家庭账号（查绑定未通过） | 不重发；跳设置页（第 7 屏）提示“设备未绑定”，引导绑定；拍题流程终止 |
| 40002 | 400 | 请求体不是 JPEG / 体缺失 | 不重发；提示“照片格式不对，请重拍”，回取景器（第 3 屏） |
| 40101 | 401 | 未鉴权：缺 token 或 token 失效 | 不重发；提示“请检查设备绑定”，跳设置页 |
| 41301 | 413 | 超 8MB | 不重发原图；终端先压缩到 8MB 以内再由用户手动重拍 / 重发；连续两次 413 则提示“照片太大，请靠近一点拍” |
| 41501 | 415 | 非 JPEG（如 PNG、HEIC） | 不重发；终端转码为 JPEG 后由用户手动重发；转码失败则回取景器重拍 |
| 42901 | 429 | 限流 | 按通用 429 处理；处理页不谎称在判题 |
| 50301 | 503 | 模型未接通（判题解题服务 / 上游不可用） | 提示“判题服务暂时接不通，稍后再试”；留在第 3 屏或回第 2 屏，不进处理页假装点亮五阶段 |
| 40003 | 400 | `Idempotency-Key` 缺失或格式错 | 不重发；终端补 key 后由用户手动重发 |

- **失败分支（C2 必补）**：网关拒收（40001 / 40101 / 41301 / 41501 / 50301）时终端停在第 3 屏（取景器）或第 2 屏，不进第 4 屏处理页；处理页五阶段只在 A1 成功建 job 后才开始点亮。原型里五阶段恒亮、无拒收分支，那是演示，不得当作已实现。

### A2　GET /solve/{job_id} —— 查判题进度与结果（F1）（未定：U1；U2 已定：轮询）

- **方法＋路径**：`GET /solve/{job_id}`，`{job_id}` 为 A1 返回的任务 ID。
- **请求头**：`X-Terminal-Id`、`Authorization: Bearer`（同 A1）。无请求体。
- **轮询约定（已定，U2，2026-11-16）**：真实进度不推、只轮询——不建 WebSocket、不接 SSE、不接第三方推送。终端在处理页（第 4 屏）轮询本接口，间隔 1 秒一次、最多 60 秒，超时按 `50401` 处理；五步全亮才进思路页（第 5 屏）；离开本屏取消未决步骤（见 A12）。定轮询的理由：网关是纯 HTTP 服务（骨架 Python 标准库，无 WebSocket 服务端），板子与手机都是 HTTP 客户端，五阶段状态已在 job 里（`stage`／`stage_index`，五阶段名 `uploading`／`gateway`／`model`／`nlp`／`delivering` 已定），轮询 1 秒一次足够点亮五步；推状态要另起长连接服务端，超出第一版范围。
- **返回（成功，`code: 0`）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `data.job_id` | string | 同 A1 |
| `data.status` | string，必填 | `processing` 处理中／`done` 完成／`failed` 失败 |
| `data.stage` | string，必填 | 五阶段当前值：`uploading`／`gateway`／`model`／`nlp`／`delivering`；`status=done` 时为 `delivering` 已完成 |
| `data.stage_index` | integer（0–5） | 已点亮的阶段数，供处理页点亮用 |
| `data.questions` | array | `status=done` 时返回，每题一项（见下）；处理中为空数组；失败时为空数组 |
| `data.failure_reason` | string／null | 失败时必填，见失败分支表 |

- **每题一项（`data.questions[i]`，`status=done` 时）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `question_id` | string | 本批内题 ID；同一批同一题只扣一次、防重扣都凭它 |
| `question_index` | integer | 第几题（从 1 起），对应“共 N 题第 M 题” |
| `correct` | boolean | 对错：`true` 做对了／`false` 做错了；第一版只判最终结果，不判过程 |
| `thinking` | string | 思路：第一句“这个题做对了／做错了”，下面分步运算，每步写算什么、算出什么，最后一步停在还差最后一下的地方，不给答案 |
| `answer` | string／null | 答案与完整过程。**未解锁时一律 `null`，不返回**；扣卡成功后再次调 A2（或调 A4 扣卡返回）才给值 |
| `unlocked` | boolean | 本题答案是否已解锁（已扣过卡） |

- **失败分支（C2 必补）**：

| `status` / 码 | 含义 | 终端收到后怎么做 |
|---|---|---|
| `failed` ＋ `failure_reason: recognition_failed` | 识别失败：没拍到题／拍糊了／模型没读出题 | 处理页不进思路页；提示“没看清题目，请重拍”，回取景器（第 3 屏）重拍；重拍是新发一次 A1（新 `job_id`），不是续旧任务 |
| `failed` ＋ `failure_reason: model_unavailable` | 模型未接通 | 提示“判题服务暂时接不通”，回第 2 屏；可手动重拍，不自动循环 |
| `failed` ＋ `failure_reason: no_question` | 图里没有题目（空白题） | 提示“这张里没有题目”，回取景器；空白题不直达答案 |
| 404 | `job_id` 不存在 / 已过期 | 提示“任务已过期，请重拍”，回第 2 屏 |
| 50401 | 轮询超时（建议 60 秒，待定） | 提示“处理超时，请重拍或稍后再试”，回第 2 屏；旧 job 由服务端自行回收，终端不再轮询 |

- **注意**：原型处理页五阶段按固定时间依次点亮（`SEND_DURATIONS [500,500,1100,600,500]`），那是演示；真实进度以本接口 `stage`／`stage_index` 为准。

### A3　POST /cards/check —— 查卡（F1、F2）

- **方法＋路径**：`POST /cards/check`
- **请求头**：`X-Terminal-Id`、`Authorization: Bearer`；`Content-Type: application/json`。
- **请求字段**：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `question_id` | string | 是 | A2 返回的题 ID；不填时只查余额，不查单题解锁状态 |
| `batch_id` | string | 否 | 本批拍题批次；填了用于“同一批同一题只扣一次”的判定，格式未定 |

- **返回（成功，`code: 0`）**：`data.balance`（integer，今日剩余张数，服务端为准，≥0）、`data.daily_total`（integer，每日张数，默认 5，最大 9）、`data.advanced`（integer，已预支张数）、`data.unlocked`（boolean，该题是否已解锁）、`data.can_deduct`（boolean，有卡且未解锁时为 `true`）。
- **错误码**：通用 401（未绑定 / 未鉴权，跳设置页）；其余通用码按总表处理。查卡失败时终端不按本地余额扣卡、不进结果页，提示“查不到余额，稍后再试”。

### A4　POST /cards/deduct —— 扣卡看答案（F1、F2）

- **方法＋路径**：`POST /cards/deduct`
- **请求头**：同 A3，另加 `Idempotency-Key`（必填，防重扣、连点重复扣）。
- **请求字段**：`question_id`（string，必填）、`batch_id`（string，否）、`job_id`（string，否）。
- **行为**：点右上角“解题卡 N 张”直接扣 1 张，无确认弹窗（原型行为）；有卡直接扣、无卡不扣；同一批同一题只扣一次，已解锁再点不扣卡直接进结果页；余额不为负，网关强制校验；多端并发以服务端实时结算为准。
- **返回（成功）**：`data.balance`（扣后剩余）、`data.unlocked`（`true`）、`data.question_id`、以及本题的 `answer`（string，完整过程＋答案，扣卡成功才返回）。终端拿到 `answer` 后进结果页（第 6 屏）。
- **错误码**：

| 码值 | HTTP | 含义 | 终端收到后怎么做 |
|---|---|---|---|
| 40201 | 402 | 无卡（余额为 0） | 不扣、不进结果页；转领取页（第 8 屏），给预支／申请两个入口 |
| 40901 | 409 | 已解锁 / 重复扣（同一批同一题已扣过） | 不再扣；直接进结果页（以服务端 `unlocked=true` 为准） |
| 40004 | 400 | `question_id` 不存在 | 提示“题目不存在”，留在思路页 |

### A5　POST /cards/advance —— 预支 1 张（F3）（U11 已定：默认 0）

- **方法＋路径**：`POST /cards/advance`
- **请求头**：同 A4（含 `Idempotency-Key`，必填，每笔留痕凭它去重）。
- **请求字段**：无请求体字段（每次固定 1 张，不接受数量参数；要改数量不走本接口）。
- **行为**：每次 1 张，不限次数，每笔留痕；上限＝每日张数×倍率，总可用＝每日张数×（1＋倍率）；到上限停，余额不许成负数。
- **返回（成功）**：`data.balance`（预支后余额）、`data.advanced`（累计已预支张数）、`data.advance_limit`（当日预支上限）、`data.remaining_advance`（还能预支几张）。
- **错误码**：

| 码值 | HTTP | 含义 | 终端收到后怎么做 |
|---|---|---|---|
| 40301 | 403 | 到预支上限 | 提示“今天预支已到上限”，留在领取页，不再发请求 |
| 40902 | 409 | 重复提交（同一 `Idempotency-Key` 已记过一笔） | 按第一次的结果显示，不多记一笔 |

- **已定**：预支倍率默认值 0（2026-11-16，见 U11；原型 1 只是演示值）。倍率可改范围 0–3，每日张数最大 9。

### A6　POST /applications —— 发申请单（F3）（U4：假问题，开发时定）

- **方法＋路径**：`POST /applications`
- **请求头**：同 A4（含 `Idempotency-Key`，必填；申请一次是一次，重复提交不累计次数）。
- **请求字段**：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `terminal_id` | string | 是 | 16 位设备 ID，与头 `X-Terminal-Id` 一致，不一致时 400 |
| `question_id` | string | 否 | 为哪道题申请的卡；不填表示通用申请 |
| `note` | string | 否 | 学生留言，最长开发时定；原型无此字段，本文档不强制 |

- **行为（按原型和 PRD 改过的三处写）**：发完**停留在领取页**，只显示“申请已发送。”，不自动回思路页；状态仍为待批；点右上角拐弯箭头或 Home 键才离开。PRD v5.2 第 290 段“发过去即回思路页”与之打架，已确认是漏改、PRD v5.3 已改，见附录 D1。
- **返回（成功）**：`data.application_id`（string，申请单 ID，格式开发时定）、`data.status`（`pending` 待批）、`data.created_at`。
- **错误码（C2 必补：申请发送失败分支）**：

| 码值 | HTTP | 含义 | 终端收到后怎么做 |
|---|---|---|---|
| 42201 | 422 | 申请发送失败（服务端创建失败 / 推送侧拒收以外的创建失败） | **留在领取页**，提示“申请没发出去，点‘发送申请’再试一次”，保留撤回前的状态；不谎称“申请已发送。”；不自动回思路页 |
| 40903 | 409 | 已有一张待批申请单（同一终端 / 同一题待批中，防重复申请） | 提示“已有一张申请在等审批”，显示已有的那张，不新建 |
