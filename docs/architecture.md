# 架构与边界

## 一、三段式

```
[手机壳] --HTTP(图片)--> [网关 :8000] --HTTP--> [桥接 :8001] --CDP--> [本机 Chrome] --HTTPS--> [网页模型]
   ↑                          ↓
   └──── 纯文本（按标题分段） ──┘
```

- **壳**只管显示与交互：拍题、切卡、锁答案、扣卡、家长确认。不碰模型、不存题库。
- **网关**只管一件事：把一张图变成「有结构的文本」。含分段、题号归一、输出后校验。
- **桥接**只管一件事：把一张图送进网页模型并取回回答。含账号组、风控停手、冷却。

三者可独立重启，互不阻塞：桥接挂了网关仍能返回明确的失败原因，壳仍能换题/重拍。

## 二、为什么是减法版

| 砍掉的 | 原因 |
| --- | --- |
| 多提示词组全量 | 组合数膨胀，无法逐条复现失败；减法版只保留一组固定护栏 |
| 多 web AI 轮询 | 并发即多账号同时在线，风控风险成倍；减法版单账号组串行 |
| L0–L3 分层题库 | 与「拍一张、只给思路」的主线无关，先不做 |
| 防抄袭 / 学情 / 错题本 | 都是需要长期数据才成立的功能，早期做等于伪需求 |

保留的三件事：**拍得到、分得清、锁得住**。

## 三、关键约定

1. **标题即结构**：模型输出必须带 `【第N题·思路】` / `【第N题·过程与答案】` / `【第N题(k)·思路】` 这类标题，壳按标题切卡。裸 `(k)` 行继承最近大题号，拆成独立小题卡。
2. **题号沿用**：原题有编号就沿用它，没有才从 1 顺序编。避免「第一行第1题」与「沿用原题号」互相打架。
3. **思路段不放答案**：提示词里先禁，输出后再校验一次（正则命中「答案/结论字样、选项直给、填空直给、方程解、行尾数值」即判定为泄题）。
4. **校验只记日志，不硬堵**：命中后孩子端给一句能行动的话，原文进 `validate_blocked.jsonl` 供家长/开发回看。
5. **风控即停**：滑块出现就停当前账号组、冷却一段时间，不做硬解、不连刷。

## 四、故障域

| 故障 | 表现 | 处理 |
| --- | --- | --- |
| 桥接进程死 | `/solve` 报「千问桥接不可用」 | launcher/看门狗拉起；壳仍可重拍 |
| Chrome 起不来 | 桥接 `/health` 无浏览器 | 清 profile 单实例锁后重启 Chrome，不走管道锁 |
| 网页模型拒答 | 返回一句礼貌拒绝 | 不当成题目结果返回；停该账号组并冷却 |
| 思路段泄答案 | 校验命中 | 只记日志 + 孩子端提示，不阻塞 |
