## 4. Tag 与版本号规则

格式统一 **`v<MAJOR>.<MINOR>.<PATCH>`**（语义化版本，参照任务文档举例 `v2.0.0`）：

| 场景 | 格式 | 例 |
| --- | --- | --- |
| 产品正式发布 | `v<M>.<m>.<p>` | `v2.0.0` |
| 预发布 | `v<M>.<m>.<p>-rc.<N>` | `v2.0.0-rc.1` |
| 热修 | `v<M>.<m>.<p>+hotfix.<N>` | `v2.0.0+hotfix.1` |
| 版本管理基线（非产品发布） | `v<M>.<m>.<p>-baseline-<YYYYMMDD>` | `v2.0.0-baseline-20261109` |
| 组件／网关独立基线 | `gw-v3.23-<说明>-<YYYYMMDD>` | 已有 `v3.23-card-preborrow-floor-8000-taskC-20261030` 属历史命名，**保留不改** |

规则：
1. **一律 annotated tag**（`git tag -a`，带说明人、日期、对应批次、对应交付包 SHA），不用轻量 tag。
2. tag **不可移动**；打错就新打一个并作废说明，绝不 `git tag -f` 覆盖已发布 tag。
3. 产品版本 `v2.0.0` 与网关组件版本 `v3.23` 是两条线，**不互相覆盖**；仓库现存唯一 tag 是网关组件封版，保留。
4. 每个 tag 必须能在交付包里找到对应的逐文件 SHA 清单（`manifest.json`），可复算才算有效版本。
5. 重大发布同时建 GitHub Release，正文写清包含什么、不含什么、已知未修项（照抄上游 Release 的「边界（照实写）」写法）。

## 5. 交付包后什么时候同步（时机表）

| 时点 | 动作 | 产出 |
| --- | --- | --- |
| T+0（交包瞬间） | 本地交付包 zip 落盘，记外层字节＋SHA-256，包内 `manifest.json` 逐文件 SHA | 不可变快照 |
| 验收通过后 T+1 工作日内 | 把该批**版本元信息**（清单／办法／说明／回执）推到 `dev`；源码发布版另等裁定 | `dev` 新 commit，commit message 带批次号与包 SHA |
| 验收通过且 Nyx 明确「合 main」 | `dev → main` 合并，**同时打 tag** ＋建 Release | tag + Release 链接 |
| 验收不通过（Request changes） | 只修交付包，**不动 `main`、不打 tag**；`dev` 上保留原 commit 供追溯 | 修订包 + 新 commit |
| 每 10 批或每月 | 做一次「三方对账」：Gitee 主账本 ↔ GitHub ↔ 本地清单，出差距表 | 对账记录 |

> 硬规则：**未验收不进 `main`、未打包不打 tag**。回滚与追责全靠这条。

## 6. 回滚办法（三档，从轻到重）

### 6.1 文件级：拿回某个历史文件
```bash
git log --oneline -- <path>          # 找版本
git show <commit>:<path> > <临时文件> # 先导出到临时文件，人工比对
# 确认无误后再覆盖工作区；原始文件先复制一份带 .bak 后缀
```
适用：单个文档／单个源码文件回退。**禁止**直接 `git checkout` 覆盖未提交的本地改动。

### 6.2 提交级：撤销某次提交（保留历史）
```bash
git revert <commit>                  # 生成反向提交，历史不丢
git push origin dev
```
适用：已推到 `dev` 的错误同步。**不使用** `git reset --hard` + 强推。

### 6.3 版本级：整体回到某个 tag
```bash
git tag -l                           # 列可用版本
git show <tag>                       # 看该版本清单
git checkout -b rollback/<tag>-<日期> <tag>   # 从 tag 拉新分支核对，绝不在 main 上直接跳
# 核对通过后，由浩爷/Nyx 决定是合并回 dev/main，还是仅取用文件
```
适用：整版回退。**禁止**在 `main` 上 `git reset --hard <tag>`；**禁止** `git push --force`。

### 6.4 兜底：GitHub 之外还有两份
- 本地每批交付包 zip（含 `manifest.json`）是**离线不可变副本**，GitHub 挂了也能从包里逐文件还原。
- Gitee 是主账本，冲突以 Gitee 为准；需要以 Gitee 覆盖 GitHub 时，**报 Nyx 裁定后执行**，WBC 不自行决定。

## 7. 清单与证据规范（可复算）

每批交付包必须含：
1. `manifest.json`：包内每个文件的相对路径（ASCII、正斜杠）、字节数、SHA-256；
2. 外层记录：zip 总字节数＋SHA-256，写进汇报；
3. 证据文件：API 原始响应摘要、本地逐文件 SHA 清单、上游文件 SHA 对照；
4. `00_INDEX.md`：ASCII 条目名 ↔ 中文原名映射。

校验方式：解包后逐文件重算 SHA-256 与 `manifest.json` 比对，0 缺失／0 不符／0 未登记才算 PASS。**只核读未实测的项必须标「待核实」，不写成已验。**
